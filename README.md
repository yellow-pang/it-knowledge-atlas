# IT Knowledge Atlas

IT 지식을 체계적으로 이해하고 개념을 연결하며, 매일 짧은 복습을 통해 기술사 답안에 필요한 설명 능력까지 기르는 개인 학습 프로젝트입니다. 흩어진 기술 메모와 단순 암기만으로는 지식의 관계와 설명 근거를 지속적으로 관리하기 어렵다는 문제에서 출발합니다.

이 프로젝트는 IT 전문지식 학습, 장기적인 기술사 대비, 직접 설계·개발·운영하며 실무 기술을 배우는 세 가지 목표를 함께 추구합니다. 기술은 실제 필요에 따라 도입하며 개발 자체가 일상적인 학습 경험을 희생하지 않도록 합니다.

주 사용자는 Mac mini에서 개발·운영하고 스마트폰과 데스크톱 브라우저로 학습하는 개인입니다. 일반 IT 개념을 공통 원본으로 삼고 정보관리기술사 학습에 우선 연결하며, 컴퓨터시스템응용기술사는 검증된 자료를 확보한 뒤 확장합니다. 일반 학습 분야는 공식 시험 분류가 아닙니다.

## 첫 MVP 제안

- 오늘의 새 개념과 복습 대상, 개념 상세 및 관련·선행 개념 이동
- 자기 평가와 다음 복습일 계산, 분야별 학습 현황
- 매 학습에서 기술사 관점의 키워드·목차 회상을 안내하고, 확인된 시험 자료가 있으면 출처와 함께 연결
- 출처와 검증 상태 표시; 문제나 공식 기준이 미확인이면 비워 둠

Mobile First로 하루 5~10분 학습을 목표로 합니다. 상세 범위와 완료 조건은 [MVP](docs/mvp.md)를 참고하세요.

## 제안 구성과 진행 상태

초기 데이터베이스로 PostgreSQL을 채택합니다. Mac mini와 OrbStack에서 기본 운영을 확인했으며 장기 운영과 복구는 추가 검증이 필요합니다. Markdown + Git을 콘텐츠 원본으로 유지하고 PostgreSQL은 개인 기록과 향후 재생성 가능한 검색 인덱스를 담당합니다. Next.js App Router, React, TypeScript와 Tailwind CSS로 개발 환경을 구성했으며 shadcn/ui는 필요한 컴포넌트가 생길 때만 검토합니다. 첫 MVP는 온라인 우선이며 서버 연결이 필요합니다. 오프라인 읽기와 복습 기록 동기화는 후속 단계입니다. 복습은 우선 단순한 명시적 규칙으로 시작하고 `ts-fsrs`는 실제 사용 후 평가합니다. 선택 근거와 대안은 [아키텍처](docs/architecture.md)와 [DB 선택 기록](docs/decisions/001-database-selection.md)에 정리했습니다.

현재는 개념 학습, 오늘의 학습·진도·복습, 로컬 Markdown 콘텐츠 등록과 소수의 공식 시험 자료 연계를 구현했습니다. 5-C-2에서 Mac mini에 운영 앱을 배포하고 기존 Cloudflare Tunnel을 통한 HTTPS 접속과 기본 인증·복습 저장을 확인했습니다. 백업·복원, 재부팅 복구와 삼성 인터넷 상세 사용성은 남았습니다. 확인 범위는 [운영 배포 안내](docs/production-deployment.md#5-c-2-배포와-검증-결과)를 따릅니다.

1. 설계와 공식 자료 확보 범위 확인 — 완료
2. 개념 읽기·관계 이동·회상 안내 — 완료; 실제 스마트폰의 전체 학습 동선 검증은 남음
3. 진도·복습 저장 — 구현 및 운영 DB 저장 확인; 지속 사용과 복구 검증은 남음
4. 로컬 Markdown 등록·가져오기 — 구현; 새 콘텐츠의 앱·DB 연계 흐름은 통합 검증 필요
5. 기술사 출제기준·기출문제 참조 연계 — 구현; AI 원문 대조 후 독립 검토와 실제 스마트폰 검증 필요
6. 운영 배포·기본 외부 접근 — 완료; 5-D에서 모바일 상세 사용성·백업·복원·재부팅 복구 검증
7. 필요성에 따라 답안 연습과 오프라인 기능 확장 — 계획

기존 `yellow-pang/yelloh-pang-lab`은 오픈소스 분석·실험 저장소로 유지하고, 이 프로젝트에서는 필요할 때 출처 링크로 참조합니다. 자동 수집은 MVP에 포함하지 않습니다.

## 개발 환경 실행

Node.js 22.12 이상과 npm이 필요합니다. `npm ci` 후 `npm run dev`를 실행하고 [오늘의 학습](http://127.0.0.1:3002)을 엽니다. 개발 앱은 기본적으로 `127.0.0.1:3002`를 사용하므로 운영 앱이 이 포트를 사용 중이면 개발 앱을 별도 포트로 실행하고 개발용 `APP_ORIGIN`도 맞춰야 합니다. 인증에는 DB가 필요하며 DB 연결 실패 시 로그인과 개인 기록 저장을 사용할 수 없습니다.

개발 DB 연결을 확인하거나 마이그레이션을 사용할 때는 OrbStack과 Docker Compose가 필요합니다. 개발 DB는 `127.0.0.1:55432`를 사용합니다. 포트가 이미 사용 중이면 확인 후 로컬 설정을 조정하세요.

1. `.env.example`을 `.env.local`로 복사하고 개발 전용 비밀번호를 생성해 두 항목에 같은 값으로 설정합니다. URL에서 특수문자를 쓰려면 URL 인코딩이 필요하므로 영문·숫자 비밀번호를 권장합니다. 이 파일은 Git에 포함하지 않습니다.
2. `docker compose --env-file .env.local up -d --wait`로 개발 DB를 시작합니다.
3. 셸과 `.env.local`의 `DATABASE_URL`이 프로젝트 전용 개발 DB를 가리키는지 확인한 뒤 `npm run migrate -- up`을 실행합니다. 기존 DB나 볼륨을 초기화하지 않습니다.
4. 아래 로그인 설정을 마친 뒤 앱을 실행하고 로그인하여 [DB 연결 확인](http://127.0.0.1:3002/api/db-check)을 엽니다. 서버에서 `SELECT 1`을 실행하고 성공 여부만 반환합니다. 연결 확인만으로 마이그레이션 적용 여부를 확인할 수는 없습니다.

`npm test`, `npm run content:check`, `npm run typecheck`, `npm run lint`, `npm run build`로 검사합니다.

Codex 샌드박스에서는 기본 Turbopack 빌드가 내부 포트 바인딩 제한으로 `EPERM`을 반환할 수 있습니다. 5-C-1에서 `npx next build --webpack`이 성공했고, 5-C-2에서는 운영 Dockerfile의 기본 `npm run build`를 포함한 이미지 빌드가 성공했습니다.

개발 DB는 프로젝트 전용 Compose 볼륨에 저장됩니다. `docker compose --env-file .env.local stop`은 컨테이너만 중지하며 데이터를 보존합니다. 볼륨은 백업이 아니고 `down -v`는 데이터를 삭제합니다. 비밀번호는 DB 최초 생성 시 적용되며 기존 볼륨의 비밀번호를 자동 변경하지 않습니다. 운영 데이터는 이 환경에 넣지 않습니다. DB 포트는 루프백에만 게시하지만 OrbStack의 컨테이너 직접 접근 등 다른 경로는 별도 점검이 필요합니다. DB 확인 경로는 개발 환경에서도 로그인해야 하며 운영에서는 404입니다.

스키마 변경은 PostgreSQL 전용 `node-pg-migrate`를 사용합니다. ORM 없이 스키마 변경을 관리하기 위한 선택입니다. `npm run migrate -- create 변경이름`으로 마이그레이션을 만들고 검토한 뒤 `npm run migrate -- up`으로 적용합니다. 명령은 `.env.local`의 `DATABASE_URL`을 읽으므로 실행 전 반드시 개발 DB를 가리키는지 확인하세요. 학습 상태와 복습 이력 마이그레이션을 적용해야 저장할 수 있습니다. 운영 배포와 백업·복구는 [운영 배포 안내](docs/production-deployment.md)를 따릅니다.

운영 구성과 병합 후 배포·백업 절차는 [Mac mini 운영 배포](docs/production-deployment.md)를, 배포할 때의 설정·검증 기록은 [운영 배포 점검표](docs/deployment-checklist.md)를 참고하세요. 최종 운영 서비스는 병합된 main의 검증된 커밋으로 실행합니다.

## 개념 콘텐츠 작성

현재 다섯 개 개념의 목록·상세와 관계 이동, 기술사 관점의 회상 안내 및 진도·복습 저장을 제공합니다. DB 연결 실패 시 기록은 표시하거나 저장할 수 없지만 인증된 사용자는 개념을 읽을 수 있습니다. 운영 앱은 배포됐으며 콘텐츠 갱신에는 검증과 재배포가 필요합니다.

다섯 개 콘텐츠는 공식 자료와 대조했으나 독립 검토 전이므로 `needs_review`를 유지합니다. 2단계 개념 학습 화면은 Safari 반응형 모드에서 일부 동작을 확인했습니다. 3단계 평가 화면의 브라우저 조작과 실제 스마트폰 사용성은 아직 검증하지 않았습니다. 자세한 범위와 남은 검증은 [MVP](docs/mvp.md#모바일-검증)를 따릅니다.

직접 작성과 기존 Markdown 가져오기 절차는 [콘텐츠 관리 안내](docs/content-workflow.md)를 따릅니다.

`content/concepts/*.md`가 원본입니다. 파일명과 관계없이 `id`가 안정적인 식별자이며, 제목 변경이나 파일 이동 시에도 유지합니다. Front Matter는 YAML의 부분집합인 **JSON 객체**를 `---` 사이에 작성합니다. 별도 파서 의존성 없이 엄격하게 검사하기 위한 제한이며, 본문은 빈 줄로 구분한 일반 Markdown 문단만 지원합니다. 제목·목록·링크 등 다른 Markdown 구문은 현재 렌더링하지 않습니다. 기존 파일을 예시로 사용하세요.

`domains`는 일반 분야 ID 배열, `relations`는 대상 ID와 `prerequisite`(이 개념의 선행 개념), `related`, `compare` 유형의 배열입니다. 역방향 관계는 자동 생성하지 않습니다. `examAreaIds`는 예약 필드이며 현재 빈 배열만 허용합니다. 시험 연결은 별도 시험 자료에서 개념 ID를 참조합니다. 공식 원문을 대조하기 전에는 출제 사실을 추정하지 않습니다. `sources`에는 URL, 확인일과 대조 범위를 남기고, `verification`과 `aiAssistance`를 별도로 기록합니다. 검토 기록 기능이 아직 없으므로 `verified`는 허용하지 않습니다.

`summary`는 30초 요약이고 본문은 원리와 사례를 담은 3분 학습 설명입니다. `recall.question`에는 개념별 회상 질문을, `recall.answer`에는 먼저 생각한 뒤 확인할 키워드 또는 목차를 작성합니다. 답안은 저장하지 않습니다.

`npm run content:check`는 모든 파일의 형식, 필수 값, 중복 ID와 관계 참조를 검사합니다. 앱도 콘텐츠를 읽을 때 같은 검사를 수행하고 오류가 있으면 실패합니다. 콘텐츠 수정 후 `npm test`와 함께 실행하세요. 기술사 회상 질문은 일반 학습 과제이며 기출문제가 아닙니다. 시험 자료는 `content/exams/*.md`에 별도 버전과 출처로 관리하며 같은 명령으로 참조를 검사합니다. 격리 수준을 2023~2026 및 2027~2030 기준의 DBMS 관련 항목과 제137회 3교시 4번에 연결했습니다. 두 버전에서 격리 수준을 DBMS 항목에 연결한 것은 공식 원문의 직접 명시가 아닌 해석입니다. AI가 공식 원문과 대조했으며 독립 검토는 남았습니다.

## 복습과 테스트

평가일은 Asia/Seoul 기준이며 다시·어려움·기억남은 각각 1·3·7일 뒤 복습합니다. 이 규칙은 개인화 알고리즘이 아니라 초기 학습 흐름을 위한 고정 규칙입니다. 이력과 현재 상태는 한 트랜잭션에 저장하며 삭제된 콘텐츠의 기록도 보존합니다. 저장 응답을 받지 못하면 현재 상세 화면에서 같은 요청으로 재시도할 수 있습니다. 요청 ID는 화면을 떠나거나 새로고침하면 유지되지 않으므로, 응답을 받지 못한 상태에서 화면을 벗어나면 기존 요청으로 재시도할 수 없고, 다시 평가하면 이력이 중복될 수 있습니다. DB 연결 또는 마이그레이션이 없으면 오늘의 진도를 표시하지 않습니다.

통합 테스트 `tests/review.integration.mjs`는 마이그레이션을 적용한 **별도의 빈 로컬 `atlas_test` DB**와 그 DB에 연결한 테스트 서버가 필요합니다. `TEST_DATABASE_URL`과 `TEST_APP_URL`을 지정하여 `node --test tests/review.integration.mjs`로 실행합니다. 테스트는 이력과 테스트용 DB 트리거를 생성하므로 개발·운영 DB에서 실행하지 마세요. 테스트 덤프의 별도 DB 복원을 확인했으며 운영 백업의 별도 볼륨 복원은 아직 검증하지 않았습니다.

## 개인 로그인 설정

개발 DB에 인증 마이그레이션을 적용한 뒤 터미널에서 `node scripts/auth/password-hash.mjs`를 실행해 16자 이상의 긴 비밀번호를 입력합니다. 입력은 표시되지 않으며 생성되는 `.env.auth-hash`는 Git에서 제외됩니다. 이 파일의 `AUTH_PASSWORD_HASH` 값을 `.env.local`에 옮기고 파일 권한과 보관에 주의하세요. 기존 파일이 있으면 덮어쓰지 않습니다. 새로 생성한 해시는 `scrypt:...:...` 형식입니다. 이전 `scrypt$...$...` 형식도 지원하지만 Next.js의 `.env.local`에서는 각 `$`를 `\$`로 이스케이프하고, Compose의 `.env.production`에서는 값 전체를 작은따옴표로 감싸야 합니다. 셸에 직접 설정할 때도 확장을 방지하세요. `AUTH_USERNAME`은 단일 계정 ID, `APP_ORIGIN`은 브라우저에서 접속하는 정확한 출처(스킴·호스트·포트), `AUTH_SESSION_DAYS`는 1~30일입니다. 개발 기본 출처는 `http://127.0.0.1:3002`입니다. 비밀번호나 해시를 공유하거나 로그에 남기지 마세요.

로그인 시 무작위 세션 토큰을 HttpOnly, SameSite=Lax 쿠키에 저장하고 DB에는 SHA-256 해시와 만료 시각만 저장합니다. 기본 30일은 짧은 모바일 재방문에서 반복 로그인을 줄이기 위한 절대 만료 기간이며 연장되지 않습니다. 로그아웃은 서버 세션을 삭제합니다. IP나 입력한 ID와 관계없이 모든 유효한 로그인 실패가 하나의 전역 카운터에 쌓입니다. 성공하면 카운터가 초기화되고, 5번째 실패 후 15분 동안 새로운 로그인을 제한합니다. 실패 횟수에는 별도 시간 창이 없으며 이미 발급된 세션은 제한하지 않습니다. 타인이 고의로 실패를 반복해 본인의 로그인을 막을 수 있는 한계가 있습니다. 시도 제한은 PostgreSQL에 유지되고 앱 재시작으로 초기화되지 않습니다. 잠금 해제는 기다리거나 신뢰할 수 있는 관리자가 DB의 `auth_attempt` 행을 초기화합니다. 비밀번호 분실 시 새 해시를 설정하고 앱을 재시작한 뒤 기존 세션도 폐기하세요. DB 관리 권한으로 `DELETE FROM auth_session;`을 실행하면 모든 기기에서 다시 로그인해야 합니다. 이 명령은 복습 기록을 변경하지 않습니다.

세션 만료 중 평가 저장이 거부되면 현재 화면을 유지한 채 새 탭에서 로그인하고 같은 평가를 다시 저장하세요. 화면을 닫으면 재시도 ID가 사라지므로 응답을 받지 못한 기존 저장을 중복할 수 있습니다. 삼성 인터넷 실기기 동작은 아직 확인하지 않았습니다.
