# 운영 배포 설정·검증 점검표

이 문서는 배포 때마다 사용할 **미실행 점검표**다. 현재 운영 환경을 확인했거나 배포했다는 뜻이 아니다. 실행 절차와 백업·복원 방법은 [운영 배포 안내](production-deployment.md)를 따른다. 인증과 접근 보호를 검증하기 전에는 인터넷에 공개하지 않는다.

배포할 때 이 문서를 참고해 저장소 밖의 접근이 제한된 개인 기록에 결과를 남긴다. 항목별로 확인일, 확인·실패·미확인·해당 없음 중 상태와 필요한 후속 작업을 기록한다. 검증하지 않은 항목은 완료로 표시하지 않는다. 기록에는 비밀번호, 비밀번호 해시, 세션 토큰, DB 접속 URL, 환경 파일 내용, 개인 학습 기록을 넣지 않는다. 로그나 `docker compose config` 전체 출력에도 비밀값이 포함될 수 있다.

## 배포 대상과 변경 확인

- [ ] 배포 일자, 검증된 main 커밋과 콘텐츠 리비전, 최초 배포 또는 갱신 여부를 기록한다.
- [ ] 기존 운영 서비스·포트·디스크 여유를 확인하고 개발용 DB와 운영용 DB·볼륨·계정을 구분한다.
- [ ] 배포할 커밋의 `.env.production.example`, `compose.production.yaml`, 관련 문서를 비교해 추가·변경·삭제된 설정과 마이그레이션을 확인한다. 이 점검표도 변경에 맞춰 갱신한다.
- [ ] 기존 기록이 있는 DB의 스키마를 변경하기 전 백업 상태와 복구 방법을 확인한다. 개인 기록 사용 전 Mac 외부 백업과 별도 DB·볼륨 복원 검증은 [운영 배포 안내](production-deployment.md#백업과-복원)를 따른다.

## 운영 환경 변수

아래는 현재 Compose 구성 기준이다. 값이 설정됐는지와 검증 결과만 기록한다. `.env.production`은 `.env.production.example`을 바탕으로 운영용으로 별도 작성하고 접근을 제한한다. 기존 DB 비밀번호를 바꿀 때는 환경 파일뿐 아니라 해당 DB 역할도 함께 변경해야 한다. 셸에 같은 이름이 있으면 env-file보다 우선할 수 있다.

| 변수 | 배포 시 확인할 내용 |
| --- | --- |
| `POSTGRES_PASSWORD` | 운영 DB 관리자용. 앱 DB 비밀번호와 다른 긴 영문·숫자 무작위 값을 안전하게 설정한다. |
| `APP_DB_PASSWORD` | 운영 앱 DB 계정용. 관리자 비밀번호와 다른 긴 영문·숫자 무작위 값을 안전하게 설정한다. |
| `ATLAS_PORT` | 호스트 루프백 포트. 기본 `3002`; 다른 서비스와 충돌하지 않고 Tunnel 대상과 일치하는지 확인한다. |
| `APP_ORIGIN` | 실제 브라우저 접속 HTTPS 출처(예: `https://atlas.example.com`). 경로와 마지막 `/`는 제외하고, 비표준 포트는 포함한다. 출처 불일치는 로그인·로그아웃·복습 저장을 거부한다. |
| `AUTH_USERNAME` | 개인용 로그인 ID. 서버 측에 설정하며 공개 회원가입은 없다. |
| `AUTH_PASSWORD_HASH` | 사용자가 정한 비밀번호로 생성한 서버 측 해시. 해시 생성·기존 형식 주의사항은 [개인 로그인 설정](../README.md#개인-로그인-설정)을 따른다. 사용자는 해시가 아니라 자신이 정한 비밀번호를 입력한다. |
| `AUTH_SESSION_DAYS` | 로그인 세션의 절대 만료 기간. 1~30일이며 기본값은 30일이다. |

`DATABASE_URL`은 운영 Compose가 DB 계정과 비밀번호로 내부 접속 주소를 구성한다. 위 구성에서는 운영 환경 파일에 별도 `DATABASE_URL`을 추가할 필요가 없다. 개발·운영 설정을 혼용하지 않고 비밀값은 Git에 넣지 않는다.

- [ ] 필수 값을 운영 환경에 설정하고 환경 파일 권한을 확인했다.
- [ ] 변경된 변수의 실제 적용 여부를 비밀값을 출력하지 않는 방법으로 확인했다.

## 배포와 접근 검증

- [ ] 실제 운영 이미지 빌드(`docker compose ... build`, Dockerfile의 기본 `npm run build`)를 확인했다. 이전 webpack 빌드 성공을 운영 이미지 빌드 성공으로 간주하지 않는다.
- [ ] 대상 DB와 백업을 확인한 뒤 마이그레이션 및 앱 실행 결과를 확인했다. 기존 볼륨과 기록을 초기화하지 않았다.
- [ ] 컨테이너 상태와 `/api/health`를 확인했다. 이 확인만으로 로그인·DB 기능이 모두 정상이라고 판단하지 않는다.
- [ ] 인터넷 공개 전에 격리 HTTPS 환경에서 로그인 성공·실패, 시도 제한, 만료·로그아웃, 미인증 페이지·API 차단, 복습 저장, CSRF·원본 우회 방지를 확인했다.
- [ ] 외부 연결 작업이 별도로 승인되면 기존 Tunnel·DNS와 충돌을 확인하고, 실제 HTTPS 접속 출처와 `APP_ORIGIN` 일치 및 정상 로그인·복습 저장을 검증했다.
- [ ] 삼성 인터넷 실기기에서 최초 로그인, 자동 완성, 브라우저 재방문 시 세션 유지, 만료, 로그아웃, 학습·복습 저장을 확인했다.
- [ ] 실패·미확인 항목과 후속 작업을 기록했다. 검증되지 않은 상태에서 외부 공개하거나 기존 데이터를 삭제하지 않는다.

## 배포 기록 양식

아래를 개인 기록에 복사해 상태와 날짜만 적는다. 비밀값이나 개인 기록의 내용은 적지 않는다.

```text
배포일 / 확인일:
배포 커밋 / 콘텐츠 리비전:
대상 구분: 최초 배포 / 갱신
환경 변수 확인: 미확인
백업 및 복원 준비: 미확인
운영 이미지 빌드: 미확인
마이그레이션 및 앱 상태: 미확인
격리 HTTPS 인증·접근·복습 검증: 미확인
Tunnel·실제 HTTPS 출처 확인: 미확인
삼성 인터넷 실기기 확인: 미확인
남은 문제와 후속 작업:
```
