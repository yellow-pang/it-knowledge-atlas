# 아키텍처와 운영 방향

## 구성

단일 Next.js 애플리케이션이 반응형 화면과 서버 측 콘텐츠 조회·개인 데이터 저장을 담당한다. 브라우저는 오늘 학습, 개념 탐색, 복습과 현황을 제공한다. Markdown + YAML Front Matter는 Git으로 관리하는 개념·시험 콘텐츠의 원본이며, 서버가 읽고 ID·참조를 검증해 화면에 제공한다. SQLite는 개인 진도와 복습 이력만 저장한다. 외부 서비스나 큐는 필요하지 않다. 파일 변경을 운영에 반영하는 절차는 배포 방식에 맞춰 명시하고, 콘텐츠 파일을 사용자가 웹에서 직접 편집하는 기능은 MVP 밖에 둔다.

React와 TypeScript는 후보인 Next.js와 함께 화면 구성과 데이터 계약에 사용한다. Tailwind CSS는 반응형 스타일을 일관되게 작성하기 위한 후보이며, 기본 HTML과 CSS만으로 충분한 범위에서는 줄일 수 있다. shadcn/ui는 필수가 아니며 접근 가능한 기본 구성 요소를 직접 만들기 어려운 경우 필요한 것만 도입한다. Markdown은 Git에서 검토·수정하기 쉽고 SQLite는 단일 사용자 데이터 운영이 간단하다. 대안인 모든 데이터의 DB 저장은 콘텐츠 변경 이력 관리가 더 복잡해지고, 파일만으로 개인 이력을 기록하면 동시 저장과 일관성 처리가 어려워진다.

복습은 [MVP의 명시적 규칙](mvp.md)으로 시작한다. `ts-fsrs`는 개인화의 필요성과 이력 호환·마이그레이션 비용을 확인한 뒤 검토한다. 기술 선택은 제안이며 아직 설치·구현되지 않았다.

## PWA와 연결 실패

첫 MVP는 온라인 우선이며 서버 연결이 필요하다. 연결이 없으면 읽기와 기록 저장을 보장하지 않으며 저장되지 않은 상태를 알린다. 오프라인 읽기와 복습 기록 동기화는 후속 단계다. 먼저 정상 학습·서버 저장 및 실패 안내를 검증한다.

이후 설치 가능성, 앱 셸과 최근 열어 본 콘텐츠의 제한적 읽기 캐시를 기기별로 검증할 수 있다. 캐시되지 않은 콘텐츠는 오프라인에서 열 수 없음을 표시하고, 콘텐츠 갱신·캐시 무효화 정책을 둔다. 오프라인 복습 기록은 초기에는 지원하지 않는다. 재연결 후 다시 평가한다. 향후 지원 시 기기 내 내구성 있는 대기열, 고유 이벤트 ID, 재시도·중복 방지, 충돌 정책과 동기화 확인을 설계·검증한다.

설치 및 서비스 워커 동작은 브라우저와 기기에 따라 달라 실제 사용 환경에서 확인한다. PWA 설치나 캐시만으로 오프라인 저장이 보장되지는 않는다.

## macOS 개발·운영 분리

동일 Mac mini에서 개발 서버와 운영 서버는 별도 프로세스, 포트, 환경 설정 및 SQLite 경로를 사용한다. 예를 들어 개발 DB는 프로젝트 밖의 개발 전용 경로, 운영 DB는 사용자 홈의 별도 영속 디렉터리에 둔다. 실제 경로·포트는 구현 시 확정하고 설정에 명시한다. 운영 DB를 Git 저장소나 빌드 산출물에 두지 않고 개발 테스트가 운영 데이터를 가리키지 않도록 시작 시 경로를 확인한다. 운영은 고정된 빌드 산출물을 실행하고 개발 서버와 분리해 업데이트한다.

macOS의 `launchd`를 서비스 자동 시작·재시작 후보로 검토한다. 실행 계정의 권한, 로그 위치·회전, 실패 감지와 재시작 후 정상 동작 확인을 운영 절차에 명시한다. OS 재시동, 잠자기 및 전원 장애 후 복구는 실제 환경에서 시험해야 한다. 설정·서버 설치와 배포는 이번 설계 범위가 아니다.

## 접근 및 보안

초기에는 신뢰할 수 있는 사설 네트워크 또는 사설 VPN을 통한 접근을 우선 검토한다. 네트워크 격리만으로 모든 접근을 신뢰하지 말고 기기 접근 통제와 인증 필요성을 실제 구성에 맞춰 검토한다. 외부 공개가 필요해지면 HTTPS, 인증·인가, 비밀정보 관리, 업데이트 및 접근 로그를 갖춘 구성을 별도로 설계하고 검증한다. 인터넷 공개 포트는 현재 전제하지 않는다. 비밀정보와 운영 DB는 Git에 넣지 않는다.

## 백업과 복구

콘텐츠는 Git 이력과 원격 저장소로 관리하되 개인 데이터 백업을 대체하지 않는다. SQLite는 쓰기 중 파일을 무작정 복사하지 않고 SQLite의 온라인 백업 기능 등 일관된 방식으로 백업한다. WAL 사용 시 관련 파일과 일관성에 주의한다. 운영 데이터와 설정의 정기 백업을 Mac 외부 저장소에도 보관하고 접근 권한을 제한한다. 백업 주기·보존 기간은 허용 가능한 데이터 손실량에 맞춰 정한다. 별도 경로에 복원해 무결성과 최근 복습 기록을 확인하는 복구 연습을 주기적으로 수행하며, 운영 DB를 덮어쓰기 전 서비스를 중지하고 기존 파일을 보존한다. 구체적인 자동화는 운영 구현 시 정한다.

## 확장 경계

필요해지면 답안 시도 테이블, 시험 자료, 오프라인 동기화와 고급 복습 알고리즘을 추가할 수 있다. 지금은 다중 사용자·분산 시스템·외부 자동 수집·AI 평가를 설계의 필수 의존성으로 두지 않는다.
