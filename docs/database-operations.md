# DB 사용과 운영 준비

## 현재 개발 DB

현재 OrbStack의 PostgreSQL은 **개발·실험 전용**이다. `atlas_dev`는 PostgreSQL 관리자 권한을 가진 초기 계정이며 Mac의 root 계정은 아니다. 학습 테이블은 마이그레이션으로 구성하며 개발 DB에는 실제 운영 기록을 넣지 않는다. 접속·실행 방법은 [README](../README.md#개발-환경-실행)를 따른다.

개발 DB는 `127.0.0.1:55432`에 게시되고 프로젝트 전용 볼륨을 사용한다. 관리자 계정은 개발 중 연결과 SQL을 배우는 데 사용할 수 있지만 테이블과 데이터를 삭제할 권한도 있다. GUI DB 클라이언트는 선택 사항이다. 기존 `psql`이나 앱의 서버 측 연결 확인으로도 접속을 점검할 수 있다. 비밀번호와 접속 문자열은 Git, 스크린샷이나 공유 로그에 남기지 않는다.

## 환경 변수와 비밀번호

`.env.local`은 작업 폴더마다 별도로 준비하고 Git에 커밋하지 않는다. 같은 DB에 접속하려면 DB에 설정된 자격 증명을 사용한다. 현재 `POSTGRES_PASSWORD`는 빈 볼륨에서 DB가 처음 만들어질 때 관리자 비밀번호로 적용되고, `DATABASE_URL`은 앱과 마이그레이션의 접속 정보다.

이미 초기화된 DB의 비밀번호는 `.env.local`만 바꿔서는 변경되지 않는다. 비밀번호를 바꾸려면 DB에서 해당 계정의 비밀번호를 먼저 변경하고 사용하는 접속 정보도 갱신한다. 현재 개발 구성에서는 `POSTGRES_PASSWORD`와 `DATABASE_URL`의 비밀번호를 일치시킨다. 비밀번호 변경을 위해 볼륨을 삭제하지 않는다. PostgreSQL 이미지의 초기화 설정은 기존 데이터 디렉터리에 다시 적용되지 않는다.

셸에 이미 설정된 `DATABASE_URL`은 `.env.local`보다 우선할 수 있다. 마이그레이션은 스키마를 변경하므로 실행 전 의도한 DB인지 확인한다. 운영 구성은 별도의 DB와 접속 설정을 사용한다. 개발 명령이 운영 DB를 가리키지 않도록 실행 전 대상을 확인한다. 접속 정보를 터미널이나 로그에 출력할 때 비밀번호가 노출되지 않도록 한다.

## 실제 개인 기록을 저장하기 전

운영 구성은 격리 테스트에서 DB·볼륨·계정 분리와 재시작 후 보존을 확인했다. 최종 운영 서비스는 아직 배포하지 않았다. 다음은 배포와 실제 개인 기록 사용 전 확인 사항이며 상세 결과와 남은 복원 검증은 [운영 배포 안내](production-deployment.md)를 따른다.

1. 개발과 운영의 PostgreSQL 인스턴스, 볼륨, 포트·접속 설정 및 자격 증명을 분리한다. 개발 실험과 마이그레이션 검증에 운영 DB를 사용하지 않는다. 기존 개발 볼륨의 데이터를 운영 데이터로 간주하지 않는다.
2. 관리자 계정은 초기 설정과 관리에만 사용하고, 앱에는 필요한 권한만 가진 별도 계정을 사용한다. 스키마 변경을 위한 계정과 실행 중인 앱의 권한도 구분한다. 앱 자체 로그인과 운영 접근 통제는 [인증 전략 결정 기록](decisions/002-application-authentication.md)에 따라 구현·검증한다.
3. 학습 상태와 이력 테이블은 버전 관리된 마이그레이션으로 구성한다. 이후 테이블·제약 조건 변경도 마이그레이션 파일로 관리한다. GUI에서 SQL을 연습할 수 있지만 실제 구조는 버전 관리된 마이그레이션으로 재현한다. 별도 스키마 생성은 필수가 아니며 필요에 따라 결정한다.
4. 운영 데이터 백업을 DB 볼륨과 Mac 외부에 별도로 보관하고 접근을 보호한다. 백업 주기와 허용 가능한 데이터 손실량은 사용자가 정한다. 별도 DB와 볼륨에 복원해 기록을 확인하기 전에는 복구 가능하다고 가정하지 않는다.
5. Mac과 OrbStack 재시작 후 DB 준비와 앱 재연결을 확인한다. 스마트폰 접속 방식과 접근 통제도 실제 기기에서 검증한다.

영속 볼륨은 컨테이너 재시작 후 데이터를 유지하지만 백업은 아니다. 볼륨 삭제, 운영 DB 초기화 또는 복원으로 기존 데이터를 덮어쓰는 작업은 데이터를 먼저 보존하고 명시적으로 확인한 뒤 수행한다. 상세 설계는 [아키텍처](architecture.md#백업과-복구)와 [DB 선택 기록](decisions/001-database-selection.md)을 참고한다.
