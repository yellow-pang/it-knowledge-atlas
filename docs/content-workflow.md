# 학습 콘텐츠 등록과 가져오기

콘텐츠 원본은 `content/concepts/*.md`이며 개인 진도와 복습 이력은 별도의 PostgreSQL에 있습니다. 등록 명령은 DB에 연결하거나 기록을 변경하지 않습니다. 자료를 사용할 권리가 있는지 먼저 확인하세요. 외부 교재나 서브노트를 권리 확인 없이 복사하지 않습니다.

## 직접 작성하거나 기존 노트 준비하기

1. 프로젝트 폴더에서 터미널을 열고 의존성이 설치되지 않았다면 `npm ci`를 실행합니다. 등록할 파일은 `content/concepts` 밖의 작업 폴더에 둡니다. 아래 경로는 예시이므로 실제 경로로 바꾸고 초안과 폴더의 상위 디렉터리는 미리 준비하세요. 경로에 공백이 있으면 따옴표로 감쌉니다.
2. 새 개념은 기존 `content/concepts/transaction.md`를 작업 폴더에 복사해 작성하거나, 기존 Markdown 하나로 검토용 초안을 만듭니다.

   ```sh
   npm run content:import -- draft ~/Notes/my-note.md ~/Notes/my-note-atlas.md
   ```

   초안은 기존 파일을 덮어쓰지 않고, 원본 전체를 본문에 보존합니다. 첫 Markdown 제목이 있으면 이름에 복사하며 없으면 파일명을 사용합니다. 원본의 YAML, 태그, 링크와 관련 개념은 자동 해석하지 않으므로 초안 본문에서 확인해 적절한 필드로 직접 옮기세요. 원본은 그대로 남습니다. 여러 파일은 각각 초안을 준비합니다. 임의로 개념을 분해하거나 사실을 생성하지 않습니다.
3. `---` 사이 JSON 객체를 완성합니다. `id`는 영문 소문자·숫자를 하이픈으로 구분한 형태(예: `database-index`)로 고유하게 지정하고 등록 후 제목이나 파일명을 바꾸더라도 유지합니다. `name`, `domains`(하나 이상), `definition`, `summary`, `recall.question`, `recall.answer`, `aiAssistance`와 본문을 채웁니다. `domains`는 일반 IT 분야이며 공식 시험 분류가 아닙니다. `examAreaIds`는 현재 `[]`로 둡니다.
4. `sources`에 실제 확인한 HTTPS 출처의 `title`, `url`, `checked`(YYYY-MM-DD), `scope`를 기록합니다. 없으면 확인한 뒤 등록하세요. `relations`는 확인한 대상 ID와 `prerequisite`, `related`, `compare` 중 명시한 유형만 입력합니다. 관계가 없으면 `[]`입니다. 예시는 기존 파일을 참고하세요. 역방향 관계는 자동으로 추가되지 않습니다.
5. `verification`은 초안이면 `draft`, 사실 검토가 필요하면 `needs_review`입니다. `aiAssistance`는 AI 사용 여부와 범위를 별도로 기록합니다. 형식 검사는 사실 검증이 아닙니다. `verified`는 검토 기록 기능이 없어 현재 허용되지 않습니다. 회상 질문은 일반 연습이며 기출문제가 아닙니다.

본문은 현재 빈 줄로 구분한 문단만 화면에 표시합니다. 제목, 목록, Obsidian 위키 링크, 코드 블록 및 Markdown 링크는 서식으로 렌더링되지 않습니다. 원본과 대조해 문단으로 직접 정리하고 출처 링크는 `sources`에 기입하세요. 원본의 메타데이터는 초안 본문에 남으므로 등록 전 정리해야 합니다.

## 미리보기와 등록

파일 하나를 등록하는 예시입니다.

```sh
npm run content:import -- preview ~/Notes/my-note-atlas.md
npm run content:import -- apply ~/Notes/my-note-atlas.md
npm run content:check
```

여러 파일이 든 폴더를 등록할 때는 같은 폴더를 두 명령에 지정합니다.

```sh
npm run content:import -- preview ~/Notes/atlas-ready
npm run content:import -- apply ~/Notes/atlas-ready
npm run content:check
```

폴더는 하위 폴더까지 `.md` 파일을 읽습니다. 심볼릭 링크는 지원하지 않으며 발견 시 중단합니다. 일괄 등록 파일끼리의 관계도 검사합니다. 먼저 `preview`에서 대상 파일과 경고를 확인하고 필요한 수정을 마친 뒤 같은 경로로 `apply`를 명시적으로 실행하세요. 적용 시 다시 전체 콘텐츠와 일괄 등록 파일을 함께 검사합니다. 대상은 `content/concepts/<id>.md`입니다. 등록 후 앱에 반영하기 전에 Git 변경 내용을 검토하세요.

UTF-8로 읽은 내용이 완전히 같은 파일은 기존 콘텐츠 또는 같은 묶음에 있으면 건너뜁니다. 내용이 다른 같은 ID는 오류이며 자동 병합·덮어쓰기는 하지 않습니다. 정확히 같은 정규화 이름을 가진 다른 ID는 중복 의심 경고입니다. 이름은 앞뒤 공백 제거, 유니코드 NFKC 정규화, 소문자 변환 후 비교합니다. 유사한 이름이나 같은 의미의 다른 표현은 감지하지 못하므로 직접 확인하세요. 일부 Markdown 구문은 경고하지만 지원하지 않는 모든 구문을 감지하지는 못합니다. 다른 파일이 이미 대상 경로를 차지하면 오류입니다. 오류 메시지의 파일과 항목을 수정하고 미리보기부터 다시 실행하세요. 미확인 관계는 추가하지 말고 별도로 검토하세요. Front Matter는 일반 YAML이 아닌 JSON 객체만 허용합니다.

일반 오류가 나면 이번 적용에서 생성한 파일을 삭제해 되돌리려 합니다. 파일 권한이나 파일 시스템 오류 등으로 되돌리기 자체가 실패할 수 있으므로 오류 후에도 등록 결과와 전체 검증을 확인하세요. 다만 강제 종료나 전원 장애까지 여러 파일을 원자적으로 등록하지는 못합니다. 중단 후에는 `git status`와 콘텐츠 파일을 확인하고 `npm run content:check`를 실행하세요. `.content-import-lock`이 남으면 다른 등록 명령이 실행 중이 아닌지 확인한 후 빈 잠금 디렉터리를 삭제하고 다시 미리보기하세요. 등록 중 다른 도구로 콘텐츠를 동시에 수정하지 마세요.

## 앱에서 확인과 수정

개발 서버는 요청 시 파일을 읽지만 상세 페이지의 빌드 시점 경로·캐시 영향이 있을 수 있으므로 등록 후 `npm run dev`를 재시작하고 목록과 상세, 출처, 관계, 회상을 확인하세요. 운영은 콘텐츠를 포함해 `npm run build`로 다시 빌드하고 해당 산출물을 배포·재시작해야 합니다. 현재 자동 배포는 없습니다. 기존 파일을 수정할 때도 ID를 보존하고 `npm run content:check`, 테스트 및 동일한 반영 절차를 수행합니다.

현재 구현상 DB가 연결되어 있으면 기존 ID의 이력과 복습일은 그대로이며 이력이 없는 새 ID는 오늘의 새로운 학습에 나타납니다. 새 콘텐츠 등록부터 앱 조회와 DB 이력 보존까지의 전체 흐름은 아직 별도 테스트 DB에서 통합 검증하지 않았습니다. DB가 연결되지 않으면 목록은 읽을 수 있지만 미학습 구분과 평가 저장은 확인할 수 없습니다. 기존 ID를 다른 개념에 재사용하거나 변경하지 마세요. 콘텐츠와 개인 기록은 각각 별도 백업이 필요합니다.

## 시험 자료 관리

`content/exams/*.md`의 JSON Front Matter에 종목, 버전별 기준, 영역, 문제지와 개념 관계를 명시합니다. `information-management.md`가 형식 예시입니다. `npm run content:check`는 개념과 시험 자료의 중복 ID, 참조, 출처, 날짜와 관계 상태를 함께 검사합니다. 시험 자료의 `verified`에는 대조 기록 `review`가 필요합니다. 현재 자료의 AI 원문 대조와 독립 검토 전 상태는 이 기록에 명시되어 있으며, `verified` 자체가 독립 검토 완료를 뜻하지 않습니다. 관계에도 별도 근거 `reason`과 상태·검토 기록을 남깁니다. 출제기준 개정 시 기존 버전과 연결을 수정·삭제해 덮어쓰지 말고 새 버전의 ID와 관계를 추가합니다. 문제지 수준과 확인된 교시·번호를 구분하고 원문을 복제하지 않습니다. 2027~2030 기준의 공식 뷰어는 자료실에서 정보관리기술사를 검색해 해당 버전을 선택합니다. 형식 검사는 사실 검증을 대신하지 않습니다. 변경 후 Git에서 기존 버전과 관계가 보존되는지 확인하세요.

개념의 `examAreaIds`는 호환성을 위해 비워 두고 관계는 시험 자료의 `areaRelations`에 기록합니다. `questionRelations`도 같은 개념 ID를 사용합니다. PostgreSQL은 개인 진도·복습 기록의 원본이며 이 파일을 편집해도 DB를 수정하지 않습니다.
